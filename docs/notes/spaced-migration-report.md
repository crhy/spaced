Issue #417 ("Migration path/'assistant' from devuan/debian/ubuntu derivatives", from discussion #394) asks for a Devuan-style migration for Debian derivatives, and in the same paragraph for a Linux Mint user to install Spaced while keeping their home, get a Bazaar install queue, and be told **which apps will not be installed after the upgrade, why, and how to reinstall them manually if that's an option**. Only the last part is implementable offline, so that is what shipped: `overlays/usr/local/bin/spaced-migration-report`.

**Shipped (branch `strata/f066-spaced-migration-report`, CHANGELOG section `11.26.2-2`):**

- `spaced-migration-report --snapshot [FILE]` enumerates the `.desktop` applications on the machine it runs on — `$HOME/.local/share/applications`, every directory in `$XDG_DATA_DIRS`, and `/var/lib/flatpak/exports/share/applications` — and writes `Name<TAB>Exec<TAB>source` lines to `$HOME/.local/share/spaced-linux/migration-inventory.txt`. Under the home, so the reused-home path (`scripts/vm/qemu/install-reuse-home.sh`, issue #413) keeps it.
- With no `--snapshot` it reads that inventory (`--inventory FILE`, `-` for stdin) and compares it with the applications present now and with the Spaced application set. Each application that is gone prints one line: name, why (`Spaced does not ship it`, `Spaced ships it as <pkg> but it is not installed`, or `only in Flathub`), and the exact command the user can run: `sudo apt install <pkg>` when `apt-cache policy` reports a candidate, `flatpak install --user flathub <id>` when the Flathub remote offers the id, otherwise "not in Devuan or Flathub: keep the .desktop out of your menu". `--quiet` prints only the count; the exit code is 0 even when apps are missing, because this is a report and not a test.
- `overlays/usr/share/spaced-linux/app-set.txt`, generated by `scripts/gen-app-set.sh` from the `applications`, `file_managers` and `flatpak` groups of `config/packages.yaml` (each line `<name>\tapt|flatpak`). `config/packages.yaml` is build-side and is not installed on a live system, so the report needs a shipped copy; `scripts/check.sh` regenerates it and refuses a stale file, the way it already refuses an empty `scripts/iso/package-list.sh` output.
- `tests/test_migration_report.py` in the `tests/test_open_target.py` style: stubbed `apt-cache`, `flatpak` and `dpkg-query` in a temp `bin/`, two fake systems, all three reasons, all three reinstall lines, the missing-inventory message, `Usage:` + exit 2 for unknown arguments, and one inventory line per `.desktop` entry with nothing for malformed ones.

**Still rhY's to choose:** the Bazaar queue format and when it runs (the issue suggests the first Welcome run), the uninstall list and the reverse-migration to plain Devuan carltonhobbs-commits raised on 2026-11-15 (loonylion "Interesting idea", rhY "I like it. Will consider!"), where the migration assistant is published (this repo, `crhy/spacedwelcome`, or `crhy/spacedbazaar`), and whether the report is wired into `overlays/usr/local/bin/install-spaced-linux` — that script is deliberately untouched here, it already saves and restores `/etc/fstab.orig.calamares` and is the natural place for a migration step later.

**Why:** the issue's other halves need product decisions and another repository; the report answers the "be very clear about which apps will not be installed" sentence with no new moving parts.
**How to apply:** never let the report install or queue anything — it prints commands only. Keep `app-set.txt` generated (edit `config/packages.yaml`, then run `scripts/gen-app-set.sh`). Related: [[spaced-11261-release-state]], [[spaced-no-prs-batch-into-release]].
