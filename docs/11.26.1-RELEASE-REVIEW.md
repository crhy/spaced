## Not tested

- **Known problem, found on a real PC rather than in a VM:** updating a running
  11.26 desktop to 11.26.1 (rhY's machine, 2026-11-13 15:36) upgraded the
  `elogind` package. The old package's `prerm` ran `invoke-rc.d elogind stop` and
  the new `postinst` started the daemon again, and the restarted elogind no
  longer knew the running session: `loginctl list-sessions` printed `No
  sessions` and `/run/user/<uid>` was emptied. Until the PC was restarted,
  Flatpak applications such as Brave had no name resolution (their `resolv.conf`
  lives under `/run/user/<uid>/.flatpak-helper`), PulseAudio reported `Daemon
  startup failed`, and the menu's **Restart** asked for a password because
  `org.freedesktop.login1.Manager.CanReboot` answered `challenge`. Wi-Fi and
  Ethernet kept working, and a restart fixed everything. What is **not** tested:
  the `11.26.1-2` session guard and the restart warning were measured only in a
  QEMU live session (`.strata/out/g01-vm.txt`, `RESULT: PASS passed=4 failed=0`);
  the physical machine that hit this was never re-tested with the guard, and no
  upgrade of a running desktop on physical hardware has been repeated since.
  See the row for this in `docs/FIXES.md` and the restart warning at the top of
  `docs/releases/11.26.1/RELEASE-NOTES.md`.
- Physical hardware of any kind. Every boot, install and upgrade above ran in
  QEMU/KVM or VirtualBox with 4096 MiB, 4 CPUs and one virtual disk.
- NVIDIA, AMD and Intel graphics on real cards. The interrupted NVIDIA install
  rollback (`spaced-nvidia-helper --rollback`, the `pending` transaction state)
  is covered only by `tests/test_driver_recovery.py`; no real GPU install, no
  real power loss, no driver was ever installed in a VM.
- Multi-monitor icon placement (#406, #407, #412): no session with two physical
  or two virtual monitors was run.
- Anything judged by eye. `build/vm-tests/v03/spaced-linux-11.26.1-amd64/xkill.png`
  and `monitor.png`, and the four smoke screenshots in `build/test-artifacts/`,
  were captured and checked only for being non-blank; nobody has looked at them.
  The Monitor red/orange process buttons, the Monitor card grid, the Welcome
  highlighted button and the wallpaper dialog were never operated in a session.
- An upgrade on a real installed disk followed by a boot of the upgraded system.
  The 11.26 → 11.26.1 upgrade ran in a live session, so `update-grub` could not
  finish (`grub-probe: … 'overlay'`) and the upgraded system was never started.
- The published update repository. Only the local signed archive was tested;
  `make apt-repo-publish` and the GitHub Pages copy were not run here.
- Ventoy and other loopback media for the **Safe Graphics** and **verbose boot**
  entries; the `findiso=` change was checked in the source tree, not booted.
- A physical live USB used as a rescue stick: the rescue tools were only checked
  as present on PATH inside a VM, and never used to recover a real system.
- Reusing an encrypted (LUKS), Btrfs, XFS or NTFS `/home`; only one ext4
  `/home` partition with a UUID entry was installed.
- The 180-day `Valid-Until` behaviour against a client that has actually been
  offline past the expiry date.
- `anacron` over several days on a machine that is off at 06:00; only package
  presence was checked (`PASS: b: anacron is installed`).
- Multi-day or multi-boot soak: no long-running session, no repeated logout
  cycle, no disk-space or memory trend measurement beyond the single live
  reading `memory_used_mib=1210`, `process_count=270`.
- Non-English installers and locales, accessibility tooling, and any install
  with system encryption enabled.
