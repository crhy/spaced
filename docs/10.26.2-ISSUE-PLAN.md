# Spaced Linux 10.26.2 — issue plan

Draft written 2026-10-08 from the 23 issues open in
[crhy/spaced](https://github.com/crhy/spaced/issues). This is a plan, not a
status record: nothing here is implemented or verified yet. Items marked
**verify** are my understanding and must be checked before work starts.
For #267 and #166 only the most recent comments were read.

## How to read this

- **Delivery** says where a fix ships: a new ISO (10.26.2), an APT package
  revision (10.26.1-N), or an app release (Flatpak through `spaced-github`).
- **Pieces** are sized for the local model, one small task each, with a check
  that can run in the KVM test VM or under a virtual screen.
- Sysvinit only: none of this may introduce a systemd unit, timer or path.

## A. Point-release fixes (10.26.2)

### #282 — Brave: Safe Browsing off, no call-homes, an alternative browser

*Asked:* disable "Safe" Browsing by default; consider a DNS blocklist; add one
alternative browser to the suggested apps in Spaced Welcome.

*Where:* `overlays/etc/brave/policies/managed/spaced-extensions.json` (already
disables News, P3A, Rewards, stats ping, Web Discovery and force-installs
uBlock Origin) and the skeleton profile
`overlays/etc/skel/.var/app/com.brave.Browser/.../Default/Preferences`.

*Plan:*
1. Add the Chromium policies that turn the remaining reporting off —
   `SafeBrowsingProtectionLevel: 0`, `MetricsReportingEnabled: false`,
   `UrlKeyedAnonymizedDataCollectionEnabled: false`,
   `SearchSuggestEnabled: false`, `AlternateErrorPagesEnabled: false`,
   `BackgroundModeEnabled: false`, `DefaultBrowserSettingEnabled: false`, and
   Brave's own (AI chat, wallet, VPN, Tor, Talk, Speedreader promotions) —
   **verify** each name against the Brave version actually shipped; an unknown
   policy is ignored silently, so the check must read `brave://policy` output.
2. Measure instead of trusting the list: in the test VM start Brave from a
   fresh user with a packet capture running, leave it idle for ten minutes,
   and list every host contacted. Keep the capture summary as release
   evidence, and repeat it after the change. The article linked in the issue
   (spyware.neocities.org) is the checklist of what to look for; I have not
   read it yet.
3. DNS blocklist: only for the hosts the capture shows still being contacted
   after step 1. Ship it as its own small package that adds entries to
   `/etc/hosts` between marked lines, with a switch in Spaced Welcome.
   **Decision for rhY:** on by default or opt-in. A system-wide blocklist can
   break sites in ways users will not connect to Spaced.
4. Alternative browser in Spaced Welcome, labelled as such. Criteria from the
   issue: no telemetry, no call-homes, a Flatpak, uBlock Origin installable and
   on by default. My starting read, all **verify**: LibreWolf fits best (on
   Flathub, telemetry removed, ships uBlock Origin); Floorp is on Flathub but
   does not ship uBlock Origin; Helium and Pale Moon need their Flatpak status
   checked. Pick by running the same packet capture on each candidate.
5. `scripts/check.sh` gains assertions for the new policy keys, like the
   existing Brave default-handler checks.

*Delivery:* policy file through an APT revision (reaches installed systems);
skeleton profile and Welcome entry in the 10.26.2 ISO and a Welcome release.

*Pieces:* policy keys + check; capture script for the VM; blocklist package;
Welcome catalogue entry.

### #279 — Close / maximize / minimize hit areas still too small

*Asked:* make each button's clickable area fill its whole slot and a few
pixels beyond, without overlapping its neighbour or the corner resize grip.

*Where:* the Metacity theme files of all eleven themes under
`overlays/usr/share/themes/` (22 files; Spaced-WinXP sets `button_width`/`button_height`
to 24, 22 and 0 in different frame geometries). See `docs/MATE-theming.md`.

*Plan:* this has come back several times, so fix it by measurement.
1. Write a hit-test script for the VM: open a window, sweep the pointer across
   the title-bar's right end in 1 px steps, click, and record which pixels
   close, maximize or minimize. Output the three rectangles per theme.
2. Enlarge the button box in every frame geometry and inset the drawing so the
   icon keeps its size while the box grows; widen the right border so the box
   reaches the window edge. **Verify** that the Compiz decorator takes its hit
   area from the Metacity button box (if it does not, the fix belongs in the
   decorator settings instead).
3. Acceptance, from the script: each button at least 30 x 26 px clickable, no
   gap between buttons, at least 6 px left for the corner grip, on every theme
   at 100% and 200% scale.

*Delivery:* theme package through an APT revision and the ISO.

*Pieces:* the hit-test script; one theme at a time; a `check.sh` rule that all
themes use the same button geometry.

### #277 — Cleaning up Spaced Update

*Asked:* open on the OS Release page and check automatically; checking must not
ask for the root password, installing still must; a real progress bar with
text saying what is being updated; an in-app changelog for the version found.

*Where:* `~/spacedupdate/src/spaced-update.py` (`pkexec HELPER apt-refresh` at
line ~787; installs at ~939, ~958, ~1049) and `src/spaced-update-helper`.

*Plan:*
1. Start page and automatic check: small UI change.
2. Check without a password: give the refresh its own polkit action
   (`allow_active=yes`) that can only refresh package lists; installing keeps
   `auth_admin`. The helper must accept no arguments on that path.
   Alternative if a polkit rule is unwanted: refresh into a per-user APT state
   directory, which needs no root at all.
3. Progress: run APT with a status file descriptor and drive the bar and the
   text line from its real percentages and package names.
4. Changelog: fetch the release notes for the found version (GitHub release
   body, falling back to `CHANGELOG.md`), render inside the app, newest fixes
   first. No browser.

*Delivery:* a Spaced Update Flatpak release, plus the helper and polkit file in
an APT revision.

*Pieces:* one per numbered item; each has an existing test file to extend
under `~/spacedupdate/tests`.

## B. Voxa inside Spaced (not a point-release item)

### #283 — New Spaced Welcome with a Voxa greeter, and #238 — Full integration

A large feature, best split across the two repositories.

*In Spaced Welcome:* the two-button chooser (old Welcome or Voxa Welcome) with
recorded audio, and the "Getting things set up" progress screen that installs
Voxa, the model and the microphone defaults. Recorded audio matters here:
nothing can be synthesised before anything is installed.

*In Voxa:* a greeter mode — a scripted sequence of steps, each of which the
user can skip, with "Voxa, quit" always returning to the ordinary Welcome:
1. sound calibration (Voxa already has a calibration module; this adds the
   spoken walk-through and "Voxa, let's calibrate sound" later);
2. browser choice (default, or a grid of nine with logos);
3. the brief tutorial (3–4 minutes);
4. the offer of the long tutorial;
5. account sign-ins from #238, one service at a time.

*Depends on:* Voxa 0.1.6 being released (first-run welcome, model fitting,
installing apps through Spaced Bazaar, updating Spaced by voice).
**Decision for rhY:** which release line this targets; it is too large for
10.26.2.

*Caution for #238:* signing in to email and other accounts means handling
passwords. The plan should be that Voxa opens each sign-in page and the user
types; Voxa never hears, stores or types a password.

### #284 — Telling by tone that someone has finished speaking

This is a Voxa hearing feature; I suggest moving it to crhy/voxa. Starting
points: Voxa already has a voice detector and a text check for whether a
sentence looks complete. What is missing is prosody — falling pitch, fading
energy and a lengthened last syllable at the end of a thought. rhY's own
read-aloud recordings are labelled data to measure candidates against.
