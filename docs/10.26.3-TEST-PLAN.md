### The script

`scripts/tests/samba-network-test.sh` (copy it to each Spaced machine; run
as the desktop user, never with sudo):

- `local` checks this machine can serve: packages, smbd running **and**
  enabled at boot, port 445 listening, usershare settings, sambashare group,
  Samba password, home directory mode, folder handler, firewall rules, and
  creates a temporary Everyone/guest share exactly as Caja does and writes,
  reads back and deletes a 1 MiB file through it. Set
  `SPACED_SMB_PASSWORD` to also test authenticated access.
- `serve` publishes `~/SpacedShareTest` as `SpacedTest` (Everyone, full
  control, guests allowed) and prints the addresses to use. `serve --stop`
  removes it.
- `peer HOST [SHARE] [-U USER]` tests another machine from this one: name
  resolution (DNS and mDNS), ping, TCP 445, anonymous share list, guest and
  authenticated smbclient round trips, SMB3, a GVfs (Caja/Gigolo) mount
  with copy in and out, and whether the host appears in Network browsing.

Exit status is the number of failures; every run appends to the log.

## Part 2: AMD Xorg login failure (#298)

### Root cause

xorg-server 21.1.25 (upstream commit `0fb16f3d`) inserted a field,
`pListHead`, in front of existing members of `DamageRec` without bumping the
video driver ABI. `xf86-video-amdgpu` reads `damage->damage` directly, so
the X server crashes on start and LightDM never appears. Upstream fixed it
in `89ec935f` ("damage: Preserve existing DamageRec member offsets in stable
branch"; xorg/xserver work item 1930). Debian shipped the fix as
`2:21.1.25-2` on 2026-10-14 (Debian bug #1150321, which also lists an Intel
modesetting crash). Devuan Ceres still carries the broken
`2:21.1.25-1devuan1`. Void Linux hit the same crash (void-packages #62954).

Spaced makes this worse for AMD users: `20-spaced-amdgpu.conf` selects the
`amdgpu` driver for TearFree (issue #177), so every AMD system takes the
broken path. bigboy's display runs on NVIDIA, which is why its upgrades
worked. The `modesetting` workaround avoids the crash but loses TearFree,
which explains the pixelation Brad saw.

### Fix

1. **Rebuild xorg-server in `crhy/spaced-apt`.** Following the existing
   `patches/compiz` / `build-compiz.sh` pattern: `patches/xorg-server/`
   holds the upstream `89ec935f` patch and source checksums, and
   `scripts/iso/build-xorg-server.sh` rebuilds Devuan's
   `2:21.1.25-1devuan1` source as `2:21.1.25-1devuan1+spaced10.26.3`. Every
   binary from that source is published together (`xserver-xorg-core`,
   `xserver-common`, `xvfb`, `xserver-xorg-legacy`, `xserver-xephyr`,
   `xnest`, `xserver-xorg-dev` where built) because they depend on each
   other's exact version. APT prefers it over `-1devuan1`, and Devuan's
   own `-2devuan1`, when it arrives, sorts higher and replaces it with no
   action from us.
2. **Refuse the broken version.** `/etc/apt/preferences.d/spaced-xorg-abi`
   pins exactly `2:21.1.25-1devuan1` to priority -1 for every binary of the
   source, so terminal `apt` never installs it either.
   `spaced-update-apt-guard` also rejects any transaction that installs
   `xserver-xorg-core 2:21.1.25-1devuan1`. The guard sees the transaction
   APT computed, so it protects even the upgrade that delivers the pin.
   Both name only the broken version, so Devuan's fixed upload passes with
   nothing to lift.
3. **Rescue for systems stuck at a console login.** Add a
   `docs/troubleshooting/` page and post the steps in #298. Sign in on the
   console, then `sudo apt update && sudo apt full-upgrade` (this installs
   `+spaced10.26.3`), then reboot. If that is not possible offline, the temporary
   modesetting file from the issue gets the desktop back. Remove it after
   upgrading so TearFree returns. Brad also needs
   `sudo apt-mark unhold xserver-common xserver-xorg-core xvfb`.
4. **Leave TearFree as it is.** It stays on the fixed amdgpu driver, so
   #177 does not come back. Moving to XLibre is a separate, later decision.
5. **10.26.3 ISO** builds with the `+spaced10.26.3` packages, so the ISO is
   never built with the broken server.
6. **Build.** `make marco` builds the X server in the existing isolated
   Devuan chroot (it asks for the administrator password through pkexec).
   `scripts/iso/build-xorg-server.sh --prepare-only` verifies the pinned
   sources and the patch without root. The patched damage code is
   byte-identical to 21.1.24; all 12 CVE fixes in 21.1.25 are kept.

## Results so far

2026-10-14, bigboy (machine A, upgraded over many releases), packages from
PR #308 installed with `dpkg -i` (spaced-meta, spaced-mate-default-settings,
xserver-common, xserver-xorg-core, xvfb):

- `local`: 0 failed. The postinst made the home 0711, enabled smbd and
  spaced-wsdd at boot (wsdd runs as nobody), and folders open in Caja. With a
  temporary Samba password (set through the real helper, deleted after),
  the signed sign-in and signed round trip pass and a wrong password fails.
- `serve` + `peer bigboy.local SpacedTest -U rhy` over the LAN address
  (A to A): 11 PASS, 0 failed. This includes the guest write inside the home
  that failed before the fix, signed SMB3, GVfs copy, and Network browsing.
- `spaced-wsdd`: 192.168.88.186 fetched bigboy's WS-Discovery metadata.
- X server: built in the chroot (`BUILD EXIT 0`, including Debian's Xvfb
  test). The installed header's `DamageRec` is identical to 21.1.24. APT
  candidate is `+spaced10.26.3`. X1/X2 not run yet: the desktop holds the
  Radeon as a secondary GPU.

Still to run: everything involving machine B, Windows, the live ISO, reboot
persistence (S2, S3, S14), and X1-X8.
