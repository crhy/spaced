## Build and resume

The native Welcome artifact is pinned in `config/external-artifacts.conf`;
the local `spaced-welcome_0.1.11_all.deb` and the `v0.1.11` release asset on
`crhy/spacedwelcome` both match the pinned SHA-256. If a pinned SHA ever
outpaces the artifact you have on hand, rebuild the Welcome component and use
the verified local artifact:

```sh
make check
make release SPACED_WELCOME_DEB=/home/rhy/spaced926/components/spacedwelcome/dist/spaced-welcome_0.1.11_all.deb
make iso-smoke
```

`make marco` builds the tracked upstream fixes in an isolated chroot if their
packages are absent. `make release` runs it automatically. Build tools run on
the host through `flatpak-spawn` when the editor is sandboxed. Privilege is
needed for isolated chroots and live-build, not for changing host packages.

9.26 uses the signed `spaced-testing` APT suite. Existing users must explicitly
opt into testing; a testing release must not silently replace the production
suite. The repository builder preserves published package bytes and refuses
to overwrite a package version with different content.

`sudo bash scripts/spaced-upgrade-testing.sh --apply` is the documented
opt-in path from an earlier Spaced installation: it verifies the archive
key against its pinned SHA-256, swaps the production `spaced` suite for the
signed `spaced-testing` suite (restore-only on failure, kept on success),
requires a candidate of 9.26 or newer, refuses any plan that would change the
init system, then performs the `spaced-meta` full-release upgrade and runs
`spaced-update-helper all` for the desktop and Flatpak update path.
The bootstrap behavior is exercised in CI by
`scripts/tests/test-testing-upgrade.sh`, and the end-to-end run is verified
by installing 8.x in a VM first (see remaining acceptance below).

Local evidence: `build/audit/`, `build/upgrade-audit/`, and component build logs.
Generated ISOs, native packages and Flatpak bundles belong in release assets,
not Git history.
