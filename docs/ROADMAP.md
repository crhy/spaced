# Roadmap: improvements for later releases

This is the open half of the Spaced Linux 11.26.1 release audit of 2026-11-13: twelve audits produced 171 findings, 98 of them were fixed on the 11.26.1 branch, 3 are standing decisions by rhY, and the remaining 70 are collected here.
Priority `High` is an audit BLOCKER, or a MAJOR that affects safety, data or security; `Medium` is any other MAJOR; `Low` is a MINOR.
Rows are sorted High first inside each section, and every row names the file it is about.
The id in the first column (for example `a07-01`) is the row in the 11.26.1 audit report; two ids on one row mean two audits found the same problem.
An issue number is added to a row when the item is filed on GitHub, so the row and the issue stay linked.
Two findings are deliberately not listed as problems: the live image keeps root login over SSH with a documented password, and Samba file sharing listens from first boot.

## Security

| Priority | What | Why it matters | Where | Suggested change |
|---|---|---|---|---|
| High | `a07-01` - the live image and every ISO carry one set of SSH host keys. | openssh-server's keys are generated in the build chroot and never removed, so all live sessions of this ISO present the same keys and can be spoofed; installed systems already delete the inherited keys in 11.26.1, so only the live image is left. | `scripts/iso/99-cleanup.chroot:15`, `config/packages.yaml:178` | Delete `/etc/ssh/ssh_host_*` in the image cleanup hook and regenerate keys on the installed target with `ssh-keygen -A`, keeping the live smoke test working. |
| Low | `a08-12` - the repository signing key is taken from the first fingerprint in the shipped keyring. | During a key rotation the published index can be signed with a different key than the one clients hold, and the failure only appears on the client. | `scripts/build-apt-repo.sh:29`, `scripts/publish-apt-package.sh:26-28` | Require exactly one fingerprint record, or check the signing key against every published key before signing. |
| Low | `a02-8` - the `XDG_RUNTIME_DIR` fallback uses the predictable path `/tmp/runtime-<uid>` and never checks who owns it. | Another local user can pre-create or symlink that directory and then receive the session's PulseAudio, dconf and D-Bus files. | `overlays/etc/profile.d/spaced-xdg-runtime.sh:5` | Drop the fallback because libpam-elogind already provides `/run/user/<uid>`, or check ownership and create it with `install -d -m 700`, and cover the graphical session through `overlays/etc/X11/Xsession.d/`. |

## Login speed and background work

| Priority | What | Why it matters | Where | Suggested change |
|---|---|---|---|---|
| Medium | `a02-3` - the desktop icon repair pass runs twice at every login and forks one `gio info` per icon. | A Desktop with 20 icons costs about 44 process forks per login, and the same pass runs again after every monitor change or metadata burst. | `overlays/usr/local/bin/spaced-desktop-icon-repair:252`, `overlays/etc/xdg/autostart/spaced-desktop-icon-repair-before-caja.desktop:5` | Batch the metadata read into one `gio info` call and skip the watcher's start-up pass when the pre-Caja entry already ran. |
| Low | `a02-9` - the user directory creation loop hard-codes the English names. | A user who moved their desktop gets a stray empty `~/Desktop` recreated after every deletion, while the icon repair works in the real directory; with `HOME` unset the loop targets `/Desktop`. | `overlays/etc/profile.d/spaced-xdg-user-dirs.sh:2` | Use `xdg-user-dirs-update` if it ships, otherwise parse `XDG_*_DIR` from `~/.config/user-dirs.dirs` and skip the file when `HOME` is empty. |
| Low | `a02-12` - the "no Compiz" dialog marker is keyed on the parent PID and never removed. | A session that keeps failing graphics leaves one world-readable file per login attempt in `/tmp`, which is never cleaned. | `overlays/usr/local/bin/spaced-window-manager:48` | Key the marker on the session boot id or the display, use a state directory instead of `/tmp`, and remove it when the dialog loop ends. |
| Low | `a02-13`, `a03-9` - the Flatpak theme migration writes its marker last. | If `flatpak override` fails the marker is never created, so the one-time migration runs again at every login and the failure is invisible because the caller swallows it. | `overlays/usr/local/bin/spaced-flatpak-theme-migration:5`, `overlays/usr/local/bin/spaced-first-login-repair:7` | Write the marker before the cleanup commands, or tolerate and log the failure, so the migration cannot repeat forever. |
| Low | `a09 F9` - the image sets no memory policy for small machines. | A 4 GB machine gets stock kernel behaviour plus the always-on daemons: no `vm.swappiness`, no zram or zswap, and no low-memory killer. | `overlays/etc/sysctl.d/60-spaced-coredump.conf:1-8`, `config/packages.yaml` | Add `overlays/etc/sysctl.d/70-spaced-memory.conf` and evaluate Devuan's `zram-tools` plus a low-memory killer with a measured 4 GB VM test. |

## Graphics drivers

| Priority | What | Why it matters | Where | Suggested change |
|---|---|---|---|---|
| High | `a05-3` - NVIDIA's repository stays enabled after an install. | A later `apt full-upgrade` replaces a working driver with a newer branch with no compatibility check, no transaction record and no rollback, which is the "working 470 replaced by nonworking 550" failure the docs warn about. | `overlays/usr/lib/spaced-linux/spaced-nvidia-helper:393,399-410` | Reuse the existing disable mechanism at the end of every successful install so the repository is enabled only during a guarded transaction, or ship an apt preference pinning the installed driver version. |
| High | No audit row, accepted in 11.26.1 - nothing prompts at boot after an interrupted NVIDIA install. | The post-boot check only acts on a pending marker written by a completed transaction, so a transaction that was killed halfway leaves the machine with a black screen and no dialog; recovery is the console command `sudo spaced-nvidia-helper --rollback`, which 11.26.1 made work again. | `overlays/usr/lib/spaced-linux/spaced-nvidia-postboot.py:180`, `overlays/etc/xdg/autostart/spaced-nvidia-postboot.desktop` | Detect an interrupted transaction (the `pending` state added in 11.26.1) at first login or in the greeter and offer the recovery dialog, or start the recovery prompt from a root boot job when the marker has no "after" record. |
| Medium | `a05-4` - the only driver download is NVIDIA's keyring `.deb`, checked against a hard-coded SHA-256. | The day NVIDIA re-releases or removes that exact file, every NVIDIA install fails with code 22 and the only advice is to update Spaced Linux, which an installed 11.26.1 cannot do. | `overlays/usr/lib/spaced-linux/spaced-nvidia-helper:170-171,386-388` | Ship `cuda-keyring` in the Spaced APT repository (or in `/usr/share/spaced-linux/`) and install it from disk; if the download stays, move URL and hash pairs into a data file Spaced Update refreshes and name the expected version in the error. |
| Low | `a05-6` - the Secure Boot check runs after the prerequisite packages are installed. | A Secure Boot user is told "No graphics-driver changes were made" after build-essential, dkms, kernel headers and friends were already installed, and nothing removes them. | `overlays/usr/lib/spaced-linux/spaced-nvidia-helper:344,698-702` | Move `check_secure_boot` before `install_prerequisites`, installing `mokutil` alone first if needed. |
| Low | `a05-7` - the module dry run cannot fail. | The `modprobe -n -v nvidia` check only looks for `/bin/false` or `/bin/true` and reads the status of `tee`, so a module that cannot be loaded for the running kernel passes verification silently. | `overlays/usr/lib/spaced-linux/spaced-nvidia-helper:606-609` | Redirect the dry run to the log file instead of piping it and fail with code 42 when it exits non-zero. |
| Low | `a05-10` - dead code in the driver helper. | `run_as_desktop_user` is never called and the `desktop_user=` field written into the pending marker is never read, so the next maintainer reasons about a path that does not exist. | `overlays/usr/lib/spaced-linux/spaced-nvidia-helper:115-120,654` | Delete the function, or use it where a per-user action is intended, and drop the unread marker line. |
| Low | `a05-11` - the maintainer installer omits the AMD configuration file. | A machine maintained with `scripts/spaced-nvidia-installer.sh` lacks `etc/X11/xorg.conf.d/20-spaced-amdgpu.conf`, which the helper's AMD action requires, so AMD repair fails with code 21. | `scripts/spaced-nvidia-installer.sh:9-22` | Add `etc/X11/xorg.conf.d/20-spaced-amdgpu.conf` with mode 0644 to the `FILES` array. |

## How to use this list

File a GitHub issue for one item before working on it, and put the issue number in the row so the
row and the issue stay linked. Fixes go on a branch, are proven by `make check` and a test that
fails without the change, and ship in the next release rather than as separate pull requests: see
[docs/notes/spaced-no-prs-batch-into-release.md](notes/spaced-no-prs-batch-into-release.md).
Findings already fixed for 11.26.1 are not repeated here; the release notes and `docs/FIXES.md`
record them.
