Marco's PID namespace bug has an existing upstream repair:
[PR #786](https://github.com/mate-desktop/marco/pull/786). The two unchanged
source patches are backported to `1.26.2-6+spaced9.26.1`; runtime, development,
debug and source packages built successfully in an isolated Devuan Ceres
chroot, with no host package changes. See [patch notes](../patches/marco/README.md).
Test both sandboxed windows and genuine root-owned windows before declaring
annotation behavior verified. A broad MATE/Compiz fork is not needed for these
source-evidenced distribution fixes.

The September 8 graphics review checked Qwen's `e43f791..854eebf` handoff
against the installed driver path. Those commits did not repair the NVIDIA
assistant integration. Upstream source at
[`a3be5eed`](https://github.com/NVIDIA/nvidia-driver-assistant/blob/a3be5eed029a3c7aa7cad42389a601c69c6ddedc/nvidia-driver-assistant)
returns unversioned distro aliases, does not reliably propagate `--install`
APT failures, and chooses latest proprietary packages for some legacy cards.
The release now validates known PCI devices including subsystem matches and
legacy branches, parses a single allowlisted package without shell evaluation,
simulates a transaction that cannot remove installed packages, and checks its
actual APT status. The official Debian 12/13 keyring bootstrap packages are
SHA-256 pinned; their repository source and public key participate in recovery.

Postboot validation accepts a hardware-accelerated Intel/AMD desktop only when
NVIDIA's separate PRIME OpenGL test also succeeds. Software desktop rendering
still fails. An installation boot ID prevents checking before reboot, and the
per-installation acknowledgement prevents repeated reboot prompts. Driver
documentation no longer suggests forced branch 610, blanket NVIDIA purges,
nonexistent `config.tar` backups, or assuming SSH is preinstalled.

Targeted graphics tests cover rollback failure, preservation of administrator
edits, CUDA source/key restoration, upstream aliases, real APT failure status,
both GT 730 legacy branches, unknown and mixed-generation GPUs, hostile or
ambiguous command output, dedicated/hybrid OpenGL, software renderers, and
installation-specific reboot/acknowledgement state. These mocked checks do
not certify a physical NVIDIA module load or RX 7600 TearFree behavior.

QEMU smoke coverage is implemented in `scripts/vm/qemu/smoke-iso.sh`:
`SPACED_QEMU_FIRMWARE=bios|uefi`, default 2048 MiB/2 CPUs, optional
`SPACED_QEMU_XRES=3840 SPACED_QEMU_YRES=2160`. It uses one standard VGA device
with 64 MiB, copies writable OVMF variables into a private run directory,
checks the live user's Compiz EWMH/decorator windows and `dpkg --audit`, and
validates screenshot pixels and requested dimensions. Evidence consists of
`qemu-runtime.json`, `qemu-live.ppm`, QEMU/serial/guest logs. Mocked launch tests
cover BIOS/UEFI arguments, isolated firmware variables, 4K settings and owned
PID cleanup. **No 9.26 ISO boot or 4K VM success is claimed at this checkpoint.**
