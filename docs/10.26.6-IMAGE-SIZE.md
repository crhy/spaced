# 10.26.6 image size: squashfs block size and BCJ filter

Measured on 2026-10-23 by unpacking the root filesystem of the published
10.26.5 ISO (`live/filesystem.squashfs`, 4,248,352,485 bytes unpacked) and
recompressing the identical tree with each option set. Same machine, four
compression threads, no other change.

| mksquashfs options | Squashfs bytes | Saving |
|---|---:|---:|
| `-comp xz` (live-build default, 128 KiB blocks) | 1,566,261,248 | — |
| `-comp xz -Xbcj x86` | 1,539,850,240 | 26,411,008 (1.7%) |
| `-comp xz -b 1M -Xbcj x86 -Xdict-size 100%` | 1,435,144,192 | 131,117,056 (8.4%) |

The shipped 10.26.5 squashfs was 1,566,265,344 bytes, matching the default
row within one block, which confirms the comparison reproduces the release.

10.26.6 uses the last row (the same settings as the Arch Linux ISO), set as
`MKSQUASHFS_OPTIONS` in the Makefile and passed to `lb build`; live-build
still adds `-comp xz` itself.

Trade-off: the live session reads and decompresses 1 MiB blocks, so random
reads from the USB stick do slightly more work. The installed system is not
affected: Calamares unpacks the squashfs onto the disk. The kernel's xz
decoder includes the x86 BCJ filter (`CONFIG_XZ_DEC_X86=y`). The VM smoke tests
compare 10.26.6 live boot time with 10.26.5.
