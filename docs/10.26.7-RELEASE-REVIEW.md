# Spaced Linux 10.26.7 release review

Reviewed on 26 October 2026 from candidate commit `f485cc5`, merged through
[PR #376](https://github.com/crhy/spaced/pull/376). This review records the
final image, published package repository, tested configurations and the two
high-priority reports that still require physical-hardware evidence.

## Release fixes

- Spaced Update leaves normal stdout available to package maintainer scripts
  while APT progress uses its own descriptor, preventing DKMS and similar
  scripts from failing with `Bad file descriptor` (#373).
- Caja keeps the user's **Show Hidden Files** preference (#361 and #372), and
  Compiz Window Previews are enabled without overwriting other preferences
  (#350).
- Compiz screenshots include the capture time and collision-safe suffixes
  (#362).
- Conservative shortcut defaults, a correct desktop-ID launcher and a file
  chooser cover application, script and ordinary-file shortcuts (#351).
- Brisk Menu adds application Properties, Uninstall, Check for Updates and
  per-user Change Icon actions (#354).
- Alacarte is the menu editor and SVG files keep Eye of MATE as their default
  viewer (#372).
- Spaced GPU Driver Manager preserves a loaded proprietary NVIDIA driver that
  `nvidia-smi` confirms is working. Replacing it requires an explicit choice
  (#334).

The MATE shortcut chooser change is also proposed upstream in
[mate-control-center PR #837](https://github.com/mate-desktop/mate-control-center/pull/837).
The unrelated stale Spaced PR #312 was closed; its useful Voxa scope is now
tracked in [Voxa issue #132](https://github.com/crhy/voxa/issues/132).

## Open high-priority questions

[#334: NVIDIA GPU issue](https://github.com/crhy/spaced/issues/334) remains
open. The preventive behavior is implemented and automatically tested, but a
VM cannot prove it on the affected GTX 1060 or an existing 470-series
installation. A useful physical-machine validation should record, before and
after running the manager:

- `nvidia-smi`, `lspci -nnk` and installed NVIDIA package versions;
- the candidates the manager displays and whether **Keep current driver** is
  the default;
- package and manager logs, followed by a cold boot and another `nvidia-smi`.

The issue can close when an affected system keeps its working driver and
returns to the graphical desktop after that boot. If it fails, those records
will identify whether the remaining problem is package detection, a `.run`
installation, initramfs generation or Xorg module loading.

[#374: Flickering blank login screen](https://github.com/crhy/spaced/issues/374)
also remains open because there is not yet a reproducible cause. On the next
occurrence, collect `/var/log/lightdm/lightdm.log`, the matching greeter or
seat log, `/var/log/Xorg.0.log`, `lspci -nnk`, and display-related `dmesg`
lines. Record whether it followed a cold boot, logout, suspend/resume or GPU
driver update. Those facts should distinguish a LightDM greeter crash or loop
from an Xorg, GPU-driver or hybrid-graphics initialization failure. The next
release should make a targeted change only after that distinction is known.

The VM matrix does not certify physical NVIDIA/AMD acceleration,
suspend/resume, Wi-Fi roaming, audio-device switching or the affected
LightDM path. Neither open report should be closed from VM evidence alone.
