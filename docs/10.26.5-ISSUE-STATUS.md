# Spaced Linux 10.26.5 issue status

Audit date: 2026-10-20. This is the source-verification record for the
10.26.5 release candidate. It does not substitute automated tests for the
physical USB-audio, GPU, BIOS/UEFI installation, or visual-theme testing that
still needs to be completed before publication.

## Fixed in source

| Issue | 10.26.5 change | Release acceptance |
| --- | --- | --- |
| [#333](https://github.com/crhy/spaced/issues/333) Add Spaced and Compiz to the dictionary | New accounts receive a personal Enchant dictionary containing `Spaced` and `Compiz`. The desktop migration adds both words independently and idempotently for existing accounts, without overwriting other personal dictionary entries. | In an existing and a newly installed account, type both words into an Enchant-using editor and confirm neither is marked as misspelled. |
| [#336](https://github.com/crhy/spaced/issues/336) USB DAC hardware profile is not remembered | The audio-profile helper now records PulseAudio card profiles in the account's `~/.config/spaced/audio-card-profiles`, restores them after login/boot, and reapplies a saved profile when a USB audio card appears later. State for a temporarily disconnected USB card is retained. | Select the affected DAC's digital profile, reboot with it connected, then repeat with it disconnected during boot and connected after login. Confirm the chosen profile returns in both cases. |
| [#337](https://github.com/crhy/spaced/issues/337) 10.26.4 update requires a second run | If the main APT transaction fails, Spaced Update now runs `dpkg --configure --pending`, verifies dependencies, and retries the exact transaction once. The retry is deliberately bounded so a persistent package failure remains visible instead of looping. `spaced-mate-default-settings` also treats schema compilation and duplicate-source cleanup as non-fatal post-install maintenance. | Upgrade a representative 10.26.4 installation and confirm package configuration completes on the first user-visible run. Inject a persistent dpkg failure and confirm the helper stops after one recovery attempt with the real error. |

The screenshots attached to #337 show a downstream dpkg configuration chain
failing and a second update run succeeding, but the first/root package error
had already scrolled out of view. They do not establish that the 10.26.4
duplicate-source APT cleanup caused the failure. The 10.26.5 change therefore
addresses the observable interrupted-configuration state without assigning an
unsupported root cause.

## Automated source evidence

- `make check` passes all source, release-identity, package, theme, wallpaper,
  and script checks.
- The Python suite passes 205 tests, including simulated USB-card reconnects,
  independent/idempotent dictionary migration, and successful and persistent
  APT failure paths.
- Both GTK/Xvfb integration tests pass.
- The duplicate-source, testing-upgrade, APT-repository pruning, and package
  payload shell tests pass.

## Published upgrade evidence

- Commit `1499592` is on `main`, and its 10.26.5 packages are available from
  the signed Spaced APT repository.
- This workstation completed a real upgrade from the published 10.26.4
  packages to 10.26.5 in one transaction. All five Spaced packages report the
  intended versions and `dpkg --audit` is clean.
- GitHub Actions passed source validation, the real-dpkg release-upgrade job,
  and the website build for the pushed commit.
- Issues #333 and #337 are closed. Issue #336 remains open only for acceptance
  testing with the affected physical USB DAC.

## Evidence still required before release

- Build the clean 10.26.5 ISO and pass live and installed BIOS/UEFI boot tests.
- Exercise #336 with the reporter's physical USB DAC; its automated coverage
  uses a deterministic fake `pactl` interface rather than real hardware.
- Complete the visual and contrast audit of every theme on the locally
  installed beta desktop, including Brisk, Compiz decorations, terminals, and
  representative Flatpak applications.
- Cold-boot representative NVIDIA 10-series and legacy AMD systems to confirm
  the installer and native driver paths against physical hardware.

Issues must remain open until the fix is merged to `main`; hardware-dependent
acceptance should be recorded after testing on the affected systems.
