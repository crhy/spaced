# Spaced Linux 11.26.1 issue status

Date: 2026-11-13. One section per issue 11.26.1 delivers. Each section names the
files that changed and the result file that proves the verification, so a reader
can check the claim instead of trusting it. Where the only evidence is an
automated test, that is said plainly; no VM or hardware claim is made without a
result file. `docs/11.26.1-RELEASE-REVIEW.md` holds the full test table and the
list of what was not tested.

Everything below is delivered twice: in the `spaced-linux-11.26.1-amd64.iso`
image and as `11.26.1-1` APT packages (`spaced-meta`,
`spaced-mate-default-settings`, `spaced-themes`), plus the separately released
components Spaced Monitor 0.1.9 and Spaced Welcome 0.1.22.

## #415 — a failed package update stopped halfway and blocked the next one

- **Reported.** A Perl upgrade failed part-way; the updater hid the solver's
  output, and the damaged state made the following update fail too.
- **Changed.** `overlays/usr/lib/spaced-linux/spaced-update-helper` and
  `spaced-update.py` keep and show failed simulation output and check
  dependency and dpkg health before and after the transaction;
  `overlays/usr/lib/spaced-linux/spaced-update-apt-guard` with
  `overlays/etc/apt/apt.conf.d/60spaced-transaction-guard` refuses to unpack
  while the system is unhealthy, including for command-line APT;
  `packages/spaced-mate-default-settings/DEBIAN/postinst` and
  `packages/spaced-meta/DEBIAN/postinst` no longer let an optional cosmetic step
  leave the package unconfigured; `scripts/test-upgrade-packages.sh` makes
  historical upgrade fixtures mandatory before publication.
- **Verified.** `tests/test_update_recovery.py`, `tests/test_meta_postinst.py`,
  `tests/test_settings_postinst.py`. Repository evidence in
  `build/11.26.1-apt-candidate.log`: `Signed full-upgrade resolution passed:
  /home/rhy/spaced1126/build/upgrade-status/spaced-linux-11.26-amd64.status` and
  `All supplied package states passed. These are solver tests, not boot tests.`
  A real transaction in a VM is recorded in `.strata/out/v04-upgrade.txt`:
  `PASS: e: dpkg --audit prints nothing`, `PASS: e: apt-get check exits 0`,
  `PASS: e: /etc/apt/apt.conf.d/60spaced-transaction-guard exists`,
  `PASS: e: no Spaced package is offered again (no upgrade loop, issue #209)`.
  That run's overall line is `RESULT: FAIL passed=12 failed=1`: the one failure
  is `update-grub` failing in a live session
  (`grub-probe: error: failed to get canonical path of 'overlay'`), not a
  package step.
- **Delivered in.** 11.26.1 ISO; `spaced-mate-default-settings` 11.26.1-1 and
  `spaced-meta` 11.26.1-1.

## #414 — `xkill` had no usable cursor

- **Reported.** The window-kill pointer was missing, so `xkill` gave no visual
  feedback.
- **Changed.** The supplied artwork is built as the Xcursor `pirate` action:
  `branding/cursors/xkillcursor.svg`, `branding/cursors/build-xkill-cursor.sh`
  and `overlays/usr/share/icons/Spaced-Cursors/cursors/pirate`. Ordinary
  pointers and window close buttons are untouched.
- **Verified.** `tests/test_xkill_cursor.py` (generation and scope). In the
  final ISO: `.strata/out/v05-live.txt` — `PASS: g: an Xcursor file named pirate
  exists under /usr/share/icons`. A live screenshot was captured at
  `build/vm-tests/v03/spaced-linux-11.26.1-amd64/xkill.png`; it has not been
  reviewed by a person, so the rendering itself is not claimed.
- **Delivered in.** 11.26.1 ISO; `spaced-themes` 11.26.1-1.

## #413 — a reused `/home` disappeared from the installed `fstab`

- **Reported.** Choosing "reuse this partition as home" produced an installed
  system whose `/etc/fstab` had no `/home` entry.
- **Changed.** `overlays/etc/calamares/modules/spacedfstabguard/main.py` (plus
  `module.desc`, wired in `overlays/etc/calamares/settings.conf`) compares
  Calamares' final partition plan with the installed `fstab`, repairs only the
  one exact missing `/home` entry, and stops without touching anything when the
  plan lost the selection, is ambiguous, or the partition cannot be identified.
  `overlays/etc/calamares/modules/shellprocess@spaced-remove-live-user.conf`
  removes the live account without its home directory when `/home` is a separate
  partition, so a reuse install cannot delete the previous system's files.
- **Verified.** A real installer run on the 11.26.1 ISO in a VM:
  `.strata/out/v02-new.txt` — `RESULT: PASS fstab_home=UUID=b9c35053-d706-43b8-bf21-dacb56d4cb08 /home ext4 defaults 0 2 keep_olduser=ok keep_user=ok rescue_tools_installed=none`,
  `SCRIPT EXIT=0`. The same scenario on the old 11.26 ISO reproduces the data
  loss: `.strata/out/v02-old.txt` — `RESULT: FAIL … keep_user=LOST`,
  `SCRIPT EXIT=1`. Automated coverage: `tests/test_calamares_home_reuse.py`,
  `tests/test_calamares_live_user.py`, `tests/test_install_reuse_home_script.py`.
  The reporter's original Calamares log and disk layout were never supplied, so
  the upstream trigger is still unproven; this defends the output invariant.
- **Delivered in.** 11.26.1 ISO (the Calamares overlay). Installed systems get
  the same guard through `spaced-mate-default-settings` 11.26.1-1.

## #412, #407 and #406 — desktop icons landed outside the visible work area

- **Reported.** New, moved or hot-plugged desktop icons appeared under the panel
  or off screen, including after a monitor or panel layout change.
- **Changed.** `overlays/usr/local/bin/spaced-desktop-icon-repair` (started by
  `overlays/etc/xdg/autostart/spaced-desktop-icon-repair.desktop` and
  `…-before-caja.desktop`) reacts to desktop and Caja metadata events instead of
  polling, and keeps items inside the current monitor work area.
- **Verified.** `tests/test_desktop_reliability.py` and
  `tests/test_external_desktop_boundaries.py`, plus the boundary assertions in
  `scripts/check.sh`. No multi-monitor session was run, in a VM or on hardware:
  this is automated evidence only.
- **Delivered in.** 11.26.1 ISO; `spaced-mate-default-settings` 11.26.1-1.

## #409 — the machine segfaulted its session manager on reboot

- **Reported.** Rebooting or powering off crashed the elogind reboot helper.
- **Changed.** Two upstream fixes are carried as `patches/elogind/
  0001-fix-poweroff-reboot-segfault.patch` and `patches/elogind/
  0002-enable-xml-entity-resolution.patch`, built into
  `257.13-1+spaced11.26.1` by `scripts/iso/build-elogind.sh`, whose upstream
  test run is now reproducible.
- **Verified.** The old image reproduces the crash: `.strata/out/v01-old.txt` —
  `RESULT: FAIL elogind=257.13-1 rounds=5` with
  `e-reboot[2038]: segfault at 0 … in elogind` in every round. The 11.26.1 image
  does not: `.strata/out/v01-new.txt` and `.strata/out/v05-reboot.txt` —
  `RESULT: PASS elogind=257.13-1+spaced11.26.1 rounds=5`, `segfault=no` in all
  five reboots and the power-off. The privileged package build is recorded as
  having run all 271 chroot-safe upstream tests (268 pass, 3 skip, 0 fail) in
  `docs/11.26.1-PAUSE-HANDOFF.md`; no build log for that run is present in
  `.strata/out/`, so it is a documented claim rather than a file re-checked here.
  `tests/test_elogind_backport.py` and
  `tests/test_reboot_loop_script.py` guard the backport and the test script.
  Only QEMU was used; no physical machine was rebooted.
- **Delivered in.** 11.26.1 ISO and the `257.13-1+spaced11.26.1` elogind package
  set in the `11.26.1-1` archive.

## #408 — a damaged portal database hid Caja locations from applications

- **Reported.** Brave and Caja file dialogs lost locations because the Flatpak
  portal permission database was damaged.
- **Changed.** `overlays/etc/X11/Xsession.d/26spaced-portal-db-repair` validates
  and repairs the damaged portal state at login without a broad permission reset.
- **Verified.** `tests/test_portal_db_repair.py` (healthy, corrupt and repaired
  states). Verified by automated tests only — no portal dialog was exercised in
  a VM.
- **Delivered in.** 11.26.1 ISO; `spaced-mate-default-settings` 11.26.1-1.

## #397 — Easy Effects was offered but cannot work

- **Reported.** Spaced Bazaar offered Easy Effects, which needs PipeWire while
  Spaced ships PulseAudio, so the installed application did nothing useful.
- **Changed.** `overlays/etc/bazaar/blocklist.yaml` (with
  `overlays/etc/bazaar/bazaar.yaml`) hides Easy Effects while the distribution
  stays on PulseAudio; no audio stack was replaced in a patch release.
- **Verified.** The blocklist assertion in `scripts/check.sh`
  (`com.github.wwmm.easyeffects`). Verified by the source gate only.
- **Delivered in.** 11.26.1 ISO; `spaced-mate-default-settings` 11.26.1-1.

## #303 — no way to set a wallpaper with the right placement

- **Reported.** Setting a wallpaper from the file manager gave no control over
  cropping or placement.
- **Changed.** `overlays/usr/share/caja-python/extensions/spaced-set-wallpaper.py`
  adds **Set as Wallpaper…**, `overlays/usr/lib/spaced-linux/spaced_wallpaper.py`
  keeps a safe private copy of the image, and
  `overlays/usr/lib/spaced-linux/spaced-wallpaper-dialog` recommends crop or fit
  from the image and screen ratios and asks for the final placement.
- **Verified.** `tests/test_set_wallpaper.py` (copy and naming safety, ratio
  recommendation, usage errors). Verified by automated tests only — the dialog
  was not clicked through in a session.
- **Delivered in.** 11.26.1 ISO; `spaced-mate-default-settings` 11.26.1-1.
